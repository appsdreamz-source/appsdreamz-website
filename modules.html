Designing for GCC statutory reality

Read against the contract, not the template

Gratuity base which allowances the contract makes eligible
WPS file structure component classification, not just validation
GOSI contribution base after every salary restructure
Leave accrual contractual entitlement, not the calendar
End-of-service provision reconciled back to the balance sheet

GCC localisation is where a technically clean implementation goes wrong without ever raising a flag. A gratuity base that excludes contract-eligible allowances doesn't throw an error. Payroll runs, the payslip looks right, and the end-of-service provision on the balance sheet is understated every month until someone leaves and the accrual doesn't cover the settlement.

The same pattern sits in WPS file structures that pass validation but misclassify a pay component, in GOSI contribution bases that drift after a salary restructure, and in leave accrual that follows the calendar rather than the contract. None of it appears as a defect. All of it appears eventually as a number that has to be explained. So we start from the employment contracts and design the element set to them, rather than configuring the standard localisation and reconciling afterwards.
